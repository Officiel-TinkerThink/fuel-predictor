# Frontend experience and components

Apply when creating or changing screens, components, interaction flows, or forms.

- Build components around a clear user task and keep each responsible for one presentation concern.
- Make loading, empty, error, success, and unavailable states intentional and understandable. Preserve useful input when a request fails.
- Use semantic structure, readable labels, keyboard support, focus management, and accessible feedback by default.
- Keep presentational components focused on rendering and local interaction. Move reusable state coordination and data transformations to the closest appropriate non-visual module.
- Use clear, domain-oriented names for components, events, state, and files. Boolean names should read as questions.
- Design responsive behavior and visual hierarchy deliberately; do not rely on a single viewport or pointer-only interaction.

## Check

Before finishing, verify that the main user flow and each visible state are understandable with keyboard navigation and assistive technology.
